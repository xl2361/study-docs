异常处理是 Java 开发中非常重要的一个知识点。这两种做法是不对的：

很多新人处理异常时，不知道什么时候该 try-catch 捕获，什么时候该抛出。该捕获时盲目抛出，该抛出时盲目捕获，或者捕获了，在 catch 里什么都不做，把异常‘吞掉’。

**什么时候抛异常、什么时候 try-catch 处理异常，然后 try-catch 具体怎么处理异常？**

1. **这段代码挂了，业务还能不能继续往下走？**
2. **这个错，我当前这层代码能不能兜住？**

---

## 什么时候 try-catch

当你不想让用户察觉到异常，或不想让异常中断整个流程，就可以用 try-catch 捕获，当成"降级开关"，可以：记录日志、返回默认值、抛出友好提示等。

**核心原则：非核心功能挂了，不能把主流程也一起拖下水。**

```java
public ProductDetail getProductDetail(Long productId) {
    // 1. 查核心数据（必须成功）
    ProductDetail detail = productDao.getById(productId);

    // 2. 查推荐数据（非核心，容易失败）
    try {
        List<Product> recommendations = recommendService.getRecommendations(productId);
        detail.setRecommendations(recommendations);
    } catch (Exception e) {
        // 兜底：推荐挂了就返回空列表，保证主页面能正常看
        log.warn("获取推荐列表失败，执行降级返回空列表", e);
        detail.setRecommendations(Collections.emptyList());
    }

    return detail; // 保证商品主信息一定能返回
}
```

**捕获后怎么处理？——当“翻译官”**

**核心原则：别把底层露出来，也别把错误吞了。**

有时 try-catch 并不是为了“降级继续跑”，而是因为底层报错太复杂 (比如数据库超时、SQL语法错误)。直接把错误抛给前端，用户看不懂，还有安全隐患。这时候 catch 就要把技术异常抓住，翻译后再抛出去。

```java
public User login(String username, String password) {
    try {
        return userDao.findByUsernameAndPassword(username, password);
    } catch (Exception e) {
        // 1. 把原始技术错误记到日志里，留给程序员排查
        log.error("登录时数据库异常", e);
        
        // 2. 给用户抛出一句友好的提示，不暴露技术细节
        throw new AuthenticationException("系统繁忙，请稍后再试！");
    }
}
```

## 什么时候抛出异常

**核心原则：发现不对劲，立刻停止，别带着错往下跑。**  
典型场景：用户发起支付，但订单状态“已取消”，或支付金额跟订单金额对不上。这时候必须抛异常，打断流程。

```java
public void payOrder(Order order, Payment payment) {
    // 1. 发现条件不满足，立刻抛出，绝不往下走
    if (!"PENDING".equals(order.getStatus())) {
        throw new IllegalOrderStateException("订单状态异常，无法支付！");
    }

    // 2. 金额对不上，也立刻抛出
    if (payment.getAmount().compareTo(order.getTotalAmount()) != 0) {
        throw new PaymentAmountMismatchException("支付金额与订单不符！");
    }

    // 只有前面全过关，才会走到：执行真正的扣款
    paymentGateway.execute(payment);
}
```

## 总结


| 场景      | 处理方式              | 关键点           |
| ------- | ----------------- | ------------- |
| 非核心功能异常 | try-catch + 降级    | 日志写足，返回默认值    |
| 原始异常不友好 | try-catch + 自定义异常 | 记录原始异常，抛出友好提示 |
| 致命错误    | 直接抛出异常            | 后续无意义，立即中断    |
