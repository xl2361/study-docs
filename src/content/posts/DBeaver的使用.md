## 一、DBeaver是什么？

**DBeaver** 是一款**免费开源**的通用数据库管理工具，支持几乎所有主流数据库。

-   **DBeaver** 就像是 **Navicat** 的免费替代品。因为**Navicat** 是收费的，想要免费使用就要破解，而破解就涉及侵权。所以，很多公司为了免费又不侵权，就选择使用**DBeaver** 来替代 **Navicat** 。
-   **DBeaver** 基于 Eclipse 开发，采用 Java 编写

* * *

## 二、DBeaver的使用

### 1、连接数据库、创建库

#### 1.1 连接数据库

**步骤：**

1.  点击左上角 **「新建数据库连接」** 图标
    
2.  选择数据库类型（如 **MySQL**）
    
    ![新建连接-1](/uploads/images/2026-03-26/2bb0d21a-57ef-4375-bcab-63065f01db8a.png)
    
3.  填写连接信息：
    
    -   **服务器地址**：数据库服务器地址（`localhost` 表示本机）
    -   **Port**：MySQL默认 `3306`
    -   **Database**：数据库名（可选，连接后可选择）
    -   **用户名**：数据库用户名（如：`root`）
    -   **密码**：数据库密码
4.  点击 **「测试连接」** 验证配置
    
5.  首次连接会提示下载驱动，点击 **「下载」**
    
6.  测试通过后点击 **「完成」**
    
    ![新建连接-2](/uploads/images/2026-03-26/afd636d6-0bbd-4af3-9e6c-ab5556963cf4.png)
    

#### 1.2 创建数据库

**方法一：右键菜单**

1.  在连接名下的**数据库**上 **右键** → 选择 **「新建数据库」**
    
    ![新建数据库](/uploads/images/2026-03-26/16e06821-3ac8-4308-9e55-7f288309729b.png)
    
2.  填写数据库名、字符集、排序规则
    
    -   **数据库名**：输入数据库名称，安装公司规范命名，公司没有相关规范，就按照通用规范，比如小写优先、下划线分割、命名反应业务等。
    -   **字符集**：可以看你们别的库的字符集设置的什么，跟别的库保持一致的字符集。如果，没有其他可参考的库，推荐选择 `utf8mb4`
    -   **排序规则**：同字符集，没有可参考的推荐选择 `utf8mb4_general_ci` 或 `utf8mb4_unicode_ci`
3.  点击 **「确定」**
    
    ![新建数据库-2](/uploads/images/2026-03-26/ee41065f-0628-499d-bf5a-b1455c9fda44.png)

### 2、导出SQL脚本和执行SQL脚本

#### 2.1 导出SQL脚本（备份）

**步骤：**

1.  选中要导出的 **数据库** 或 **表**
    
2.  **右键** → **「工具」** → **「转储数据库」**
    
    ![导出sql脚本-1](/uploads/images/2026-03-26/729344c5-789a-44c9-9d6d-ff8782908fea.png)
    
3.  选择导出对象：
    
    ![导出sql脚本-2](/uploads/images/2026-03-26/0c1db708-01a5-438b-9730-255f370eec9b.png)
    
4.  导出配置
    
    该界面可以配置导出路径，导出文件名等，设置完之后点击 **开始**。
    
    ![导出sql脚本-3](/uploads/images/2026-03-26/38068a0b-a776-4053-b793-dcc087b37a76.png)
    

> 💡 **使用场景**：
> 
> -   代码版本控制时导出表结构
> -   环境迁移时导出完整数据
> -   备份重要表数据

#### 2.2 执行SQL脚本（导入）

**步骤：**

1.  选中目标 **数据库**
    
2.  **右键** → **「工具」** → **「恢复数据库」**
    
    ![导入sql脚本-1](/uploads/images/2026-03-26/e47049d5-f547-495b-9585-7935d03d620e.png)
    
3.  选择要导入的 `.sql` 文件
    
4.  点击 **「开始」** 开始导入
    
    ![导入sql脚本-2](/uploads/images/2026-03-26/4738fc32-0727-4dea-bbc8-a1884bd18c73.png)
    

> ⚠️ **新人踩坑点**：
> 
> -   大文件导入时内存不足，需要调整JVM参数
> -   SQL文件编码不对导致中文乱码（确保UTF-8编码）
> -   导入前确保选中了正确的数据库

### 3、新建表、修改表

#### 3.1 新建表

**步骤：**

1.  选中 **数据库** → 右键 → **「新建表」**
    
2.  在表设计器中添加字段：
    
    ![新建表](/uploads/images/2026-03-26/cbc8c587-d5e8-4988-8a93-6ba1b09acd14.png)
    

| 设置项 | 推荐设置 |
| --- | --- |
| 列名 | 般规范就是使用小写字母+下划线，如 user_name |
| 数据类型 | VARCHAR、INT、DATETIME 等，字段长度在类型后的括号里面设置，比如VARCHAR(50) |
| 非空 | 主键不勾选 |
| 自增 | 一般主键ID勾选 |
| 默认值 | 如 CURRENT_TIMESTAMP |
| 注释 | 添加字段注释 |
| 约束 | 这里设置主键字段 |

3.  设置索引
    
    ![新建索引](/uploads/images/2026-03-26/89b38897-5f43-4700-8961-4b567ef252db.png)
    
4.  点击 **「保存」** → **「执行」**
    

**常用数据类型：**

```sql
-- 字符串
VARCHAR(255)      -- 变长字符串（推荐）
TEXT              -- 长文本
CHAR(1)           -- 固定长度（如：性别）

-- 数字
INT               -- 整数
BIGINT            -- 长整数（主键ID）
DECIMAL(10,2)     -- 金额字段
TINYINT(1)        -- 布尔值

-- 日期时间
DATETIME          -- 日期时间
TIMESTAMP         -- 时间戳（自动更新）
DATE              -- 日期
```

💡 **命名规范**：

如果公司有命名规范就按照公司的命名规范。如果没有的话，就可以遵循如下一般规范即可。

-   表名：`t_模块名` 或 `tb_模块名`，如 `t_user`、`tb_order`
-   字段名：小写字母+下划线，如 `user_name`、`create_time`

#### 3.2 修改表结构

修改表字段，如果是开发环境、测试环境一般都可以直接修改。如果是生产环境在修改的时候，一定要确认清楚你们可不可以直接修改。如果不可以的话，确认需要走什么样的流程，然后按照流程去走。

**进入设计视图：**

-   选中表 → **右键双击** → 进入和新建表一样的界面，进行对应修改

![修改表](/uploads/images/2026-03-26/ff212fc2-4690-4b00-bca0-3e3c64a1aa0f.png)

> -   ⚠️ **注意**：
>     -   修改已存在字段的类型可能导致数据丢失
>     -   删除字段前请确认没有代码在使用
>     -   修改表结构最好**先备份**！

#### 6.1 导出CSV

**步骤：**

1.  选中目标 **表** → 右键 → **导出数据**
    
    ![导出数据-1](/uploads/images/2026-03-26/3039a79e-0d12-4a0e-8f3e-d01bf3ccdd1b.png)
    
2.  选择导出格式：**CSV**
    
    ![导出数据-3](/uploads/images/2026-03-26/55be2af1-4ce2-42ec-9149-024d9bc34e42.png)
    
3.  点击 \*\*「下一步」\*\*到如下界面 → 设置保存位置、文件名
    
    ![导出数据-2](/uploads/images/2026-03-26/1d6ccda2-cdb0-47a0-8fa9-cac9380cd5e1.png)
    
4.  点击 **「下一步」** → **「继续」**
    

#### 6.2 导入CSV

**步骤：**

1.  选中目标 **表** → 右键 → **「导入数据」**
    
    ![导入数据-1](/uploads/images/2026-03-26/c804d67a-09f7-416f-87e3-48bc2f466235.png)

    -   设置数据类型转换

> ⚠️ **新人踩坑点**：
> 
> -   Excel列顺序与表字段不匹配
> -   日期格式转换失败
> -   Excel中有合并单元格
> -   数字字段包含非数字字符
> 
> 💡 **导入前检查**：
> 
> 1.  确认列名与字段一致
> 2.  检查数据格式（日期、数字）
> 3.  删除空行和合并单元格
> 4.  备份原数据

### 7、表数据截断和清空

#### 7.1 截断（TRUNCATE）

**特点：**

-   重置自增ID
-   速度快（DDL操作）
-   不可回滚

**步骤：**

1.  选中 **表** → 右键 →**「工具」**→ **「截断」**
    
2.  确认操作
    
    ![截断](/uploads/images/2026-03-26/23594e76-cafd-4f1a-a440-481ae5fac44c.png)
    

**SQL语句：**

```sql
TRUNCATE TABLE t_user;
```

#### 7.2 删除表数据（DELETE）

**特点：**

-   不重置自增ID
-   速度较慢（DML操作）
-   可回滚
-   可加WHERE条件

**步骤：**

1.  打开表数据
    
2.  全选数据（Ctrl+A）
    
3.  按 **Delete** 键
    
4.  保存操作
    
    ![清空表](/uploads/images/2026-03-26/9bccc280-e25d-42d4-a138-f736cbaa29a5.png)
    

**SQL语句：**

```sql
-- 删除所有数据
DELETE FROM t_user;

-- 删除指定条件数据
DELETE FROM t_user WHERE create_time < '2024-01-01';
```

> ⚠️ **新人踩坑点**：
> 
> -   **混淆清空和删除**，自增ID行为不同
> -   **操作前未备份**，数据无法恢复
> -   **DELETE无WHERE条件**，清空整表
> 
> 💡 **安全建议**：
> 
> 1.  重要数据先备份（导出SQL或Excel）
> 2.  确认使用清空还是删除
> 3.  DELETE前务必检查WHERE条件
> 4.  生产环境操作要谨慎

### 8、将表里面部分记录复制成sql语句

当你需要把表里新增的记录或者表记录的更改以sql语句导出来的时候。

**步骤：**

1.  选中你要操作的记录 → **「右键」**
    
2.  根据你的需求选择 **Insert语句** 或者 **Update语句**
    
    ![将表里面部分记录复制成sql语句](/uploads/images/2026-03-26/a93b48d8-0b96-4005-95d6-f4b6715e39be.png)
    

**推荐命名规范**

| 类型 | 规范 | 示例 |
| --- | --- | --- |
| 表名 | t_模块名 | t_user、t_order |
| 字段名 | 小写+下划线 | user_name、create_time |
| 索引名 | idx_字段名 | idx_user_name |
| 主键 | id（自增） | id |
| 外键 | fk_关联表_字段 | fk_order_user_id |
